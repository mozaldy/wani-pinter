# i18n (Indonesian + English) — Design

Date: 2026-09-17
Status: Approved in chat, pending spec review

## Goal

Every screen of wani-pinter works in Indonesian (`id`, default) and English (`en`).
Users switch language at any time; the choice persists across reloads and logins.

## Scope

In scope — **UI only**:

- All UI copy: labels, buttons, headings, nav, empty states, placeholders, toasts, modal text.
- User-facing error messages returned by API routes and server actions (e.g. login failures).
- Date and number formatting.
- `<html lang>` and page `<title>` / description metadata.

Out of scope:

- Database / seed content (student names, notes, schedule topics, AI insights stored in DB).
- Gemini prompts and AI-generated output (`lib/rpp.ts`, `lib/gemini.ts`).
- The RPP / Modul Ajar print page and DOCX export — they follow the Kemendikdasmen
  format and stay Indonesian.
- Locale-prefixed URLs (`/en/...`), SEO, plural rules, languages beyond `id`/`en`.

## Architecture

### Locale selection — cookie, no URL changes

- Cookie `NEXT_LOCALE` holds `id` or `en` (1-year max-age, `path=/`, `sameSite=lax`).
- Resolution order: valid cookie → first supported language in `Accept-Language` → `id`.
- Routes, `href`s and `proxy.ts` are unchanged. Rationale: all routes except the two
  login pages are authenticated, so sub-path routing gains nothing and would require
  rewriting the proxy matcher and every link.

### Module layout — `lib/i18n/`

| File | Purpose |
|---|---|
| `config.ts` | `locales = ['id', 'en'] as const`, `Locale` type, `defaultLocale = 'id'`, `LOCALE_COOKIE`, `hasLocale()`, `intlLocale` map (`id → id-ID`, `en → en-US`) |
| `dictionaries/id.ts` | Source dictionary: a plain object (no `as const`) grouped by area |
| `dictionaries/en.ts` | `export const en: Dictionary = {...}` — must match `id` key-for-key |
| `types.ts` | `Dictionary` type derived from the `id` dictionary's shape (string leaves widened to `string`) |
| `server.ts` | `import 'server-only'`; `getLocale()` (cookies + headers), `getDictionary(locale?)` |
| `actions.ts` | `'use server'`; `setLocale(locale)` validates, writes cookie, calls `refresh()` |
| `format.ts` | `interpolate(str, vars)` for `{name}` placeholders; `formatDate(date, locale, opts)`; `formatNumber(n, locale, opts)` |
| `I18nProvider.tsx` | `'use client'` context provider holding `{ locale, dict }`; `useI18n()` hook |

`components/LanguageSwitcher.tsx` — `'use client'` ID | EN toggle calling `setLocale`
inside `useTransition`; accepts a `variant` prop for light/compact placements.

### Dictionary shape

Top-level namespaces by area: `common`, `meta`, `nav`, `auth`, `topbar`, `dashboard`,
`analytics`, `jurnal`, `penilaian`, `bank`, `catatan`, `rpp`, `admin`, `kurikulum`,
`siswa`, `settings`, `modals`, `profil`, `kepsek`, `parent`, `errors`, plus lookup
tables for data enums (see below).

Missing or extra keys in `en.ts` are compile errors, so `tsc` / `next build` is the
completeness check. No runtime fallback is needed.

### Data flow

- `app/layout.tsx` (server): `getLocale()` + `getDictionary()`, sets `<html lang>`,
  wraps `children` in `<I18nProvider locale dict>`. `metadata` becomes
  `generateMetadata()` using `dict.meta`.
- Server components (pages, layouts): call `getDictionary()` / `getLocale()` directly.
- Client components: `const { dict, locale } = useI18n()`.
- The full dictionary is serialized to the client once via the provider. Accepted
  trade-off: tens of KB, avoids per-component slicing.
- Switching: `setLocale` → cookie → `refresh()` re-renders server components; the
  provider receives the new dictionary from the root layout.
- API routes / server actions that return user-facing messages call `getDictionary()`.

### Data values vs. display labels

Indonesian literal values that are data stay unchanged in code, types, DB and queries:

- `Jadwal.status`: `selesai | aktif | mendatang`
- `Student.risiko`: `rendah | sedang | tinggi`
- `CatatanSiswa.kategori`: `positif | perhatian | akademik | sosial`
- `Student.jk`: `L | P`
- Subject names (`Bahasa Indonesia`, `Bahasa Inggris`, …) — also fed into RPP prompts
- Route segments (`/jurnal`, `/siswa`, `/orang-tua`, …) and form field `name`s

They are rendered through dictionary lookups, e.g. `dict.enums.risiko[s.risiko]`,
`dict.enums.mapel[name] ?? name`.

### Formatting

The four hardcoded `toLocaleDateString('id-ID', …)` calls and any number/percent/currency
formatting go through `formatDate` / `formatNumber` with the active locale.

### Language switcher placements

- Teacher shell: `components/shell/Topbar.tsx`
- Kepsek shell: `components/shell/KepsekSidebar.tsx`
- Parent shell: `app/(parent)/layout.tsx` header
- `app/login/page.tsx` and `app/orang-tua/login/page.tsx`
- Settings → Preferensi: the existing (currently unwired) "Bahasa" select is wired to
  `setLocale`, options reduced to Bahasa Indonesia / English.

## Rollout

1. Foundation: `lib/i18n/*`, `I18nProvider`, `LanguageSwitcher`, root layout + metadata.
2. Shells: `(app)`, `(kepsek)`, `(parent)` layouts, Sidebar, Topbar, KepsekSidebar,
   both login pages.
3. **Pattern checkpoint:** convert `/rpp` (server page with dates) and `SettingsClient`
   (client-heavy, includes the Bahasa select). Run the app, switch ID ↔ EN, show
   screenshots, get user confirmation before continuing.
4. Remaining teacher pages: dashboard, analytics, jurnal, penilaian, bank, catatan,
   admin, kurikulum, siswa/[id], rpp/[id] (RppEditor, Section, PertemuanCard,
   CreateRppForm).
5. Shared components: modals (QuickInputModal, AIPanel, ModeKelas, RaporGenerator,
   StudentDetail, Toast), ProfilTabs, AdminTabs, KurikulumExpander, HeatmapClient,
   QuickInputButton, ui.tsx.
6. Kepsek pages, parent pages, user-facing error strings in API routes and
   `app/(app)/rpp/actions.ts`.

## Verification

- `pnpm tsc --noEmit`, `pnpm lint`, `pnpm build` pass.
- A grep scan of converted files for inline Indonesian JSX text; every hit is either
  translated or confirmed as data/out-of-scope content.
- Browser pass as teacher, kepsek and parent: every route in both languages; locale
  persists across reload and logout/login; enum labels translated; RPP generation,
  print page and DOCX export still work (content stays Indonesian).

## Risks

- Accidentally translating a data value breaks queries or the proxy — mitigated by the
  explicit data-values list above and review at each rollout step.
- Longer English/Indonesian strings may overflow fixed-width UI (sidebar is 260px) —
  checked in the browser pass.
